# Redux Toolkit Post Manager — Experiment 1.2
Deployed and live at : https://reduxlab-six.vercel.app/

Combines Experiment 1.2.1 (centralized/normalized state) and 1.2.2
(memoized selectors & rendering optimization) into one working app.

## Setup
This project uses **Vite** (fast, modern, minimal — no CRA/`react-scripts`).

```
cd redux-lab
npm install
npm run dev
```
Then open the URL Vite prints (usually `http://localhost:5173`).

Other scripts:
- `npm run build` — production build
- `npm run preview` — preview the production build locally

## Where each objective is implemented

### Experiment 1.2.1 — Centralized State Management
| Objective | File |
|---|---|
| Global store | `src/app/store.js` |
| Slices (posts, platforms, drafts) | `src/features/*/*.js` |
| Normalized state (`{ ids: [], entities: {} }`) | `createEntityAdapter` in `postsSlice.js`, `platformsSlice.js` |
| CRUD reducers | `postUpdated`, `postRemoved`, `postStatusChanged`, `platformAdded`, etc. |
| Async data flow (mock API) | `fetchPosts`, `fetchPlatforms`, `addNewPost` thunks + `src/api/mockApi.js` |
| Components connected via hooks | `useSelector` / `useDispatch` throughout `src/components` and `App.jsx` |

### Experiment 1.2.2 — Selector & Rendering Optimization
| Objective | File |
|---|---|
| Basic selectors | `postsSelectors.selectAll`, `platformsSelectors.selectAll` (auto-generated by the adapter) |
| Memoized selectors (`createSelector`) | `src/features/posts/postsSelectors.js` |
| Derived state (filtered posts, grouped-by-platform, aggregate stats) | `selectFilteredPosts`, `selectPostsGroupedByPlatform`, `selectPostStats` |
| Selector factory for per-instance memoization | `makeSelectPostCountForPlatform` |
| `React.memo` to skip re-renders | `PostRow`, `PlatformFilter` |
| `useMemo` / `useCallback` to keep props stable | `PostList.jsx` |

## Why `createEntityAdapter` + `createSelector` together
- The adapter keeps posts/platforms in a normalized `{ ids, entities }` shape,
  so lookups by id are O(1) and there's no data duplication (satisfies 1.2.1's
  normalization requirement).
- `createSelector` wraps that normalized data with memoized, derived views
  (filtered, grouped, aggregated) that only recompute when their actual
  inputs change — not on every store update (satisfies 1.2.2's performance
  requirement).
- Components pair these selectors with `React.memo`/`useCallback` so a
  re-render only happens when the specific slice of derived data a
  component reads has actually changed.

## Testing the optimization (for the lab writeup)
1. Add a `console.log` inside `selectFilteredPosts` and `PostRow`.
2. Change the draft text field (dispatch `draftFieldChanged`) — notice
   neither log fires, since `drafts` isn't an input to these selectors.
3. Change the status filter — only `selectFilteredPosts` recomputes and
   only the affected `PostRow`s re-render.
